# 空间站 Space Station — 维护文档

> 最后更新：2026-07-22（v1.1.5）

## 一、项目概况

纯客户端 SPA + PWA，用于编辑 SillyTavern (酒馆) 角色卡、世界书及 AI 预设。已部署至 GitHub Pages。

- **线上地址**：`https://yuyayun.github.io/LLLabc_character_card_edit/`
- **仓库**：`https://github.com/Yuyayun/LLLabc_character_card_edit`
- **部署**：静态站点，`npm run deploy` 推送 `gh-pages` 分支
- **语言**：仅中文

### 1.1 当前维护基线

- 当前发布基线为 **v1.1.5**，`package.json` 与 `package-lock.json` 版本号保持同步。
- v1.1.5 包含：编辑页未保存修改保护、分级数据清理与关联删除、酒馆文件往返保真、预设多角色顺序保留及正则开关文案修正。
- 本轮没有 Dexie schema 迁移，不会批量改写已有角色卡、世界书或预设数据。

### 3.2 核心类型

**CharacterCard** — `src/types/index.ts:3`

完整支持 SillyTavern spec v3，包含所有标准字段 + 扩展字段。

实际实现的额外字段（相比需求文档）：
- `card_image_file?: string` — 原始文件名
- `bound_worldbook_id?: string` — 绑定的独立世界书 ID

**WorldBook** — `src/types/index.ts:71`

相比需求文档的变更：
- `recursive_scanning?: boolean` — 递归扫描开关
- entries 中的 `extensions` 对象包含 25+ 个字段（完整的酒馆世界书条目扩展规范）

**RegexScript** — `src/types/index.ts:53`

与需求文档一致，额外加了 `vectorized: boolean` 条目状态。

**Memo** — `src/types/index.ts` (新增)

灵感笔记，需求文档中不存在。独立 `memos` 表，不参与角色卡导出。

**CloudSyncConfig** — `src/types/index.ts` (v1.0.7 新增)

云同步配置。单例模式（id 固定为 `"cloud_sync"`），存储于 `cloudSync` 表。包含 `githubToken`、`gistId`、`autoUpload` 等字段。未配置时不影响任何功能。

**CloudData** — `src/types/index.ts` (v1.0.7 新增)

云同步/备份数据格式，包含角色卡、世界书、预设、API 配置、聊天会话、灵感笔记与应用设置数据，以及 `version`、`exported_at`。`cloudSync` 本身不进入同步内容，避免把 GitHub Token 随备份上传。

> **v1.0.8 云同步变更**：上传/下载改用 gzip 压缩格式（v2 文件 `_v2.json`），数据体积减少 80-85%。下载时若 v2 文件不存在则 fallback 读旧明文文件（过渡期兼容）。PWA 更新提醒确保旧客户端及时刷新至新版。

**Preset（已实现）**：完整预设编辑器，含采样参数面板、格式化模板、提示词池/列表管理、拖拽排序、酒馆 JSON 互导。预设入口与编辑路由默认开放，无额外解锁步骤。

## 六、关键设计决策

### 6.1 与需求文档的差异

| 差异 | 原因 |
|---|---|
| Tab 分栏 → 侧边栏 | 编辑器字段多（7面板），侧边栏比 Tab 更高效，且支持收起 |
| BrowserRouter → HashRouter | GitHub Pages 无服务器端 fallback |
| `crypto.randomUUID()` 改为 `generateId()` 带 fallback | 移动端 HTTP 环境无安全上下文 |
| CropDialog 取消 lazy 加载 | 移动端 lazy + Suspense 时序问题导致闪退 |
| WorldBookEntry 扩展字段完整实现 | 酒馆实际导出的 JSON 包含 25+ 个扩展字段 |
| 新增 Memo（灵感笔记） | 用户需求，独立于角色卡导出 |
| 新增强调色主题 | 用户需求，6 色可选 |
| 交互与质感覆写 | 用户提供 CSS，整合进 index.css |

### 6.2 主题系统

- CSS 变量定义在 `:root` / `.dark`，同时通过 `@theme` 块映射为 Tailwind 工具类
- `ThemeProvider` 通过 `documentElement.style.setProperty` 动态覆盖 `--primary` / `--ring`
- 偏好存储在 `localStorage`（`theme`、`accentColor`）
- `FontProvider` 通过根变量 `--app-font-family` 控制全局字体，并同步映射 Tailwind `font-sans`；显式 `font-mono` 的代码类输入仍保留等宽字体
- 字体设置存储在 `localStorage.space-station-font-settings-v1`
- 自定义字体使用唯一动态 `<link>`；CSS 和字体族验证成功前不会覆盖当前字体或写入启用状态
- 汇文仿宋、澹雅明体、寒蝉全圆体的内置 CSS 由 `src/index.css` 顶部 `@import` 加载；系统黑体与系统宋体不发起网络请求
- 字体偏好不属于 Dexie 数据，不包含在首页备份恢复或 Gist 云同步中

### 6.3 预设访问与占位条目

- 预设路由和顶部导航默认开放，不再依赖封锁 Key、`settings` 表或额外守卫；不要重新引入已删除的 `lockKey` 模块。
- `PresetPrompt.marker` 是导入数据的一部分，不是用户设置。编辑已有条目时必须沿用原值，新建条目固定为 `false`。
- 提示词列表可以根据既有 `marker` 值或酒馆常用标识符显示“占位节点”，但显示分类不得反向改写源数据。

### 6.4 世界书架构

- 角色卡可内嵌世界书（`character_book`）或绑定独立世界书（`bound_worldbook_id`）
- `EditorWorldBook` 中支持：创建内嵌、绑定已有、解绑（提取为独立）、复制条目
- `WorldBookEntryEditor` 是共享组件，`EditorWorldBook` 和 `WorldBookEditor` 共用

### 6.5 数据导入

- PNG：解析 IEND chunk 之后的 base64 JSON
- JSON：识别 spec/spec_version，自动构建 CharacterCard
- `normalizeEntryExtensions` 同时读取 `extensions` 对象和条目级字段（酒馆两种写法都兼容）
- 导入时保留原始时间戳（`parseDate` 降级逻辑）

### 7.1 发布前检查

1. 运行 `npm run lint` 与 `npm run build`。
2. 使用 `http://localhost:5173/` 检查桌面端、手机端和刷新后的状态恢复；不要与 `127.0.0.1:5173` 的旧 PWA 缓存混用。
3. 正式发布时同步 `package.json`、`package-lock.json`、`docs/更新日志.md` 与设置页用户日志中的版本状态和日期。
4. 若页面仍显示旧资源，先清理 localhost 下的 Service Worker 与站点缓存，再判断是否为代码问题。

推送源码到 master（需要 GitHub PAT 或 SSH）：
```bash
git add . && git commit -m "..." && git push
```

### 8.3 AI 对话模块（/chat）

参照需求文档 4.4：
- 导航栏：[选择角色卡] [选择预设] [选择 API 配置]
- 左侧：历史会话列表 + 新建对话按钮
- 右侧：聊天区域（用户/AI 消息）
- 底部：消息输入框 + 发送按钮

**AI 调用逻辑：**
1. 获取 Preset 中 `enabled: true` 的 prompts
2. 按 `injection_order` → `injection_position` 排序组装 system prompt
3. 对 `marker: true` 的条目，替换为角色卡对应字段内容
4. 拼接历史未隐藏消息
5. 流式（SSE）请求 API，实时渲染回复

**消息操作：**
- 隐藏/显示（标记 hidden，不删除）
- 删除消息
- 重新生成（删除上一条 AI 回复，重新请求）
- 新对话（创建新 ChatSession）

**两种使用场景：**
- 辅助写卡 — 使用写卡预设，让 AI 生成/润色角色描述、开场白等
- 测试角色卡 — 选卡 + 预设 → 对话 → 验证 AI 回复是否贴合人设

## 九、已知注意事项

1. `index.css` 中内置网络字体的 `@import url(fontsapi.zeoseven.com...)` 必须位于 Tailwind 导入和其他 CSS 规则之前，否则会产生构建警告；运行时自定义字体必须交给 `FontProvider` 的 `<link>` 管理。
2. 澹雅明体、寒蝉全圆体及自定义网络字体依赖远程 CSS/字体文件；切换失败时保留当前字体，启动恢复失败时回到汇文仿宋，不应把失败目标写成当前字体。
3. 字体设置只在当前浏览器的 localStorage 中保存，不随 IndexedDB 备份或 Gist 云同步跨设备迁移。
4. 移动端 `crypto.randomUUID()` 不可用，已通过 `generateId()` 的 Math.random fallback 处理。
5. GitHub Pages 用 HashRouter，所有 URL 带 `/#/` 前缀。
6. 推送源码分支和部署 `gh-pages` 都需要仓库写入权限，可使用已登录的 GitHub 凭据、PAT 或 SSH。
7. 灵感笔记不参与角色卡 JSON/PNG 导出，仅存于 IndexedDB。
8. 世界书条目 `extensions` 字段可能存在于 JSON 的 `extensions` 对象中，也可能直接在条目根级别，`normalizeEntryExtensions` 两处都读。
